# 博客后端项目考核文档

## 一、项目背景

请实现一个简易博客后端系统。用户注册登录后，可以发布、修改、删除自己的文章，也可以查看其他用户发布的文章。

本项目重点考察后端基础能力，包括用户认证、接口设计、权限校验、分页查询、参数校验和统一响应格式。

除了要求做的功能外，可以自己加功能接口设计也只是给个参考不要求一模一样，如果有更好的设计，可以选择自己的，注释里是需要有基本的内容描述的。同样，数据库表的形式也不要求一模一样，在能完成功能的前提下修改可以作为额外加分项。部分功能可以用redis优化，当然，要量力而行。

## 二、功能要求

### 1. 用户认证

- 用户注册
- 用户登录
- 登录成功后返回 token
- 需要登录的接口必须在请求头中携带 token

请求头格式：

```http
Authorization: Bearer {token}
```

### 2. 用户信息

- 获取当前登录用户的完整个人信息
- 修改当前登录用户的个人信息
- 修改当前登录用户密码
- 获取其他用户的公开信息

说明：

- 当前登录用户可以查看自己的邮箱、账号状态等完整信息。
- 查看他人信息时，只能返回公开字段，不能返回邮箱、密码哈希、账号状态等敏感信息。

### 3. 文章管理

- 新增文章
- 修改自己的文章
- 删除自己的文章
- 查看文章列表
- 按用户筛选文章列表
- 查看文章详情

说明：

- 用户只能修改和删除自己的文章。
- 文章删除建议使用软删除。
- 文章列表接口只返回文章摘要，不返回完整正文。
- 文章详情接口可以返回完整正文。

## 三、数据库设计


### 1. 用户表

```sql
CREATE TABLE users (
    id BIGINT UNSIGNED NOT NULL AUTO_INCREMENT COMMENT '用户ID',
    username VARCHAR(50) NOT NULL COMMENT '登录用户名，唯一',
    email VARCHAR(100) NOT NULL COMMENT '登录邮箱，唯一',
    password_hash VARCHAR(255) NOT NULL COMMENT '加密后的密码哈希',
    nickname VARCHAR(50) NOT NULL COMMENT '用户昵称，对外展示',
    avatar_url VARCHAR(255) NOT NULL DEFAULT '' COMMENT '头像URL',
    bio VARCHAR(500) NOT NULL DEFAULT '' COMMENT '个人简介',
    is_active TINYINT(1) NOT NULL DEFAULT 1 COMMENT '账号是否启用：1启用，0禁用',
    last_login_at DATETIME NULL COMMENT '最后登录时间',
    created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '注册时间',
    updated_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
    PRIMARY KEY (id),
    UNIQUE KEY uk_users_username (username),
    UNIQUE KEY uk_users_email (email),
    KEY idx_users_created_at (created_at)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='用户表';
```

### 2. 文章表

```sql
CREATE TABLE articles (
    id BIGINT UNSIGNED NOT NULL AUTO_INCREMENT COMMENT '文章ID',
    user_id BIGINT UNSIGNED NOT NULL COMMENT '作者ID',
    title VARCHAR(200) NOT NULL COMMENT '文章标题',
    content TEXT NOT NULL COMMENT '文章内容，纯文本',
    is_deleted TINYINT(1) NOT NULL DEFAULT 0 COMMENT '是否删除：1已删除，0未删除',
    views_count BIGINT UNSIGNED NOT NULL DEFAULT 0 COMMENT '浏览次数',
    created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    updated_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
    PRIMARY KEY (id),
    KEY idx_articles_user_created (user_id, created_at),
    KEY idx_articles_created_at (created_at),
    KEY idx_articles_deleted_created (is_deleted, created_at),
    CONSTRAINT fk_articles_user_id
        FOREIGN KEY (user_id) REFERENCES users(id)
        ON DELETE CASCADE
        ON UPDATE CASCADE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='文章表';
```

### 3. 设计说明

- 考核不要求草稿功能，可以不管 `is_published` 字段。
- 删除文章时更新 `is_deleted = 1`，查询列表和详情时默认只查询 `is_deleted = 0` 的文章。
- `views_count` 在查看文章详情时可以自增。

## 四、统一响应格式

所有接口统一返回以下结构：

```json
{
  "code": 200,
  "msg": "success",
  "data": {}
}
```

常见状态码建议：

| code | 含义 |
| --- | --- |
| 200 | 请求成功 |
| 400 | 请求参数错误 |
| 401 | 未登录或 token 无效 |
| 403 | 无权限操作 |
| 404 | 资源不存在 |
| 409 | 用户名或邮箱已存在 |
| 500 | 服务器内部错误 |

## 五、接口设计

### 1. 用户注册

```http
POST /api/auth/register
```

请求体：

```json
{
  "username": "zhangsan",
  "email": "test@example.com",
  "password": "123456",
  "nickname": "张三"
}
```

成功响应：

```json
{
  "code": 200,
  "msg": "注册成功",
  "data": null
}
```

要求：

- `username` 长度建议为 4 到 50 位。
- `password` 长度建议不少于 6 位。
- `email` 必须符合邮箱格式。
- `username` 和 `email` 不能重复。

### 2. 用户登录

```http
POST /api/auth/login
```

请求体：

```json
{
  "username": "zhangsan",
  "password": "123456"
}
```

成功响应：

```json
{
  "code": 200,
  "msg": "登录成功",
  "data": {
    "token": "jwt-token-example",
    "user": {
      "id": 1,
      "username": "zhangsan",
      "nickname": "张三"
    }
  }
}
```

### 3. 获取当前登录用户信息

```http
GET /api/users/me
```

需要登录。

成功响应：

```json
{
  "code": 200,
  "msg": "获取成功",
  "data": {
    "id": 1,
    "username": "zhangsan",
    "email": "test@example.com",
    "nickname": "张三",
    "avatar_url": "",
    "bio": "这个人很懒，什么都没留下",
    "is_active": true,
    "last_login_at": "2025-01-01 12:00:00",
    "created_at": "2025-01-01 12:00:00",
    "updated_at": "2025-01-01 12:00:00"
  }
}
```

### 4. 修改当前登录用户信息

```http
PUT /api/users/me
```

需要登录。

请求体：

```json
{
  "nickname": "张三吖",
  "avatar_url": "https://example.com/avatar.png",
  "bio": "热爱生活，喜欢写博客"
}
```

成功响应：

```json
{
  "code": 200,
  "msg": "修改成功",
  "data": null
}
```

### 5. 修改当前登录用户密码

```http
PUT /api/users/me/password
```

需要登录。

请求体：

```json
{
  "old_password": "123456",
  "new_password": "654321"
}
```

成功响应：

```json
{
  "code": 200,
  "msg": "密码修改成功",
  "data": null
}
```

要求：

- 必须校验旧密码是否正确。
- 新密码不能和旧密码完全相同。
- 修改成功后建议让旧 token 失效，或要求用户重新登录。

### 6. 获取指定用户公开信息

```http
GET /api/users/{id}
```

成功响应：

```json
{
  "code": 200,
  "msg": "获取成功",
  "data": {
    "id": 1,
    "nickname": "张三",
    "avatar_url": "",
    "bio": "热爱生活，喜欢写博客",
    "created_at": "2025-01-01 12:00:00"
  }
}
```

### 7. 新增文章

```http
POST /api/articles
```

需要登录。

请求体：

```json
{
  "title": "我的第一篇博客",
  "content": "这是纯文本内容..."
}
```

成功响应：

```json
{
  "code": 200,
  "msg": "发布成功",
  "data": {
    "id": 1001
  }
}
```

要求：

- 作者 ID 必须从 token 中获取，不能由前端传入。
- 标题不能为空，长度建议不超过 200 字符。
- 内容不能为空。

### 8. 修改文章

```http
PUT /api/articles/{id}
```

需要登录。

请求体：

```json
{
  "title": "修改后的标题",
  "content": "修改后的纯文本内容"
}
```

成功响应：

```json
{
  "code": 200,
  "msg": "修改成功",
  "data": null
}
```

要求：

- 只能修改自己的文章。
- 已软删除的文章不能修改。

### 9. 删除文章

```http
DELETE /api/articles/{id}
```

需要登录。

成功响应：

```json
{
  "code": 200,
  "msg": "删除成功",
  "data": null
}
```

要求：

- 只能删除自己的文章。
- 删除时执行软删除，即更新 `is_deleted = 1`。

### 10. 查看文章列表

```http
GET /api/articles?page=1&size=10
GET /api/articles?user_id=1&page=1&size=10
```

请求参数：

| 参数 | 必填 | 说明 |
| --- | --- | --- |
| page | 否 | 页码，默认 1 |
| size | 否 | 每页数量，默认 10，建议最大 50 |
| user_id | 否 | 作者 ID，不传则查询所有用户文章 |

成功响应：

```json
{
  "code": 200,
  "msg": "获取成功",
  "data": {
    "total": 100,
    "pages": 10,
    "current": 1,
    "size": 10,
    "list": [
      {
        "id": 1001,
        "user_id": 1,
        "title": "我的第一篇博客",
        "summary": "内容预览...",
        "created_at": "2025-01-01 14:30:00",
        "updated_at": "2025-01-01 15:00:00",
        "views_count": 0,
        "author": {
          "id": 1,
          "nickname": "张三",
          "avatar_url": ""
        }
      }
    ]
  }
}
```

要求：

- 只返回未删除文章。
- 默认按创建时间倒序排序。
- `summary` 可以取正文前 100 个字符。

### 11. 查看文章详情

```http
GET /api/articles/{id}
```

成功响应：

```json
{
  "code": 200,
  "msg": "获取成功",
  "data": {
    "id": 1001,
    "user_id": 1,
    "title": "我的第一篇博客",
    "content": "完整纯文本内容...",
    "created_at": "2025-01-01 14:30:00",
    "updated_at": "2025-01-01 15:00:00",
    "views_count": 1,
    "author": {
      "id": 1,
      "nickname": "张三",
      "avatar_url": ""
    }
  }
}
```

要求：

- 已删除文章不能查看。
- 查看详情时可以将 `views_count` 加 1。

## 六、权限要求

| 操作 | 是否需要登录 | 权限说明 |
| --- | --- | --- |
| 注册 | 否 | 游客可访问 |
| 登录 | 否 | 游客可访问 |
| 查看文章列表 | 否 | 游客可访问 |
| 查看文章详情 | 否 | 游客可访问 |
| 查看他人公开信息 | 否 | 游客可访问 |
| 获取自己的信息 | 是 | 只能查看自己 |
| 修改自己的信息 | 是 | 只能修改自己 |
| 修改密码 | 是 | 只能修改自己 |
| 新增文章 | 是 | 作者为当前登录用户 |
| 修改文章 | 是 | 只能修改自己的文章 |
| 删除文章 | 是 | 只能删除自己的文章 |

## 七、考核要求

- 数据库表结构正确，能成功建表。
